Bounded Live Tuning

The control sliders in the right rail update a bounded runtime configuration. Values are clamped by the backend. Change one parameter at a time and use replay plus controlled live trials before claiming an improvement.

Safety Boundary

PulseFlow does not alter clocks, voltage, fan curves, firmware, GPU power limits, or system power plans. Active control is restricted to a process explicitly launched or attached by the operator.

ARIA Verification

Run scripts\ARIA-Verify.ps1. It compiles Rust, runs unit/integration tests, checks the UI action contract, parses browser JavaScript, validates schemas, and confirms that each declared button maps to a handler and backend route.

Operator Quick Start

Monitor only: Serve mode observes the whole machine and records frames. MONITOR ONLY and UNBOUND are normal until a workload or agent is attached.

Start: enables frame recording and, when a target process exists, bounded process modulation. Pause: stops modulation while telemetry remains live. Reset: opens a new recorded session.

Quiet / Balanced / Performance: select the controller setpoint. Begin with Balanced. Change one slider at a time, press Apply Parameters, and compare saved sessions in Analytics.

Recommended learning order: Recorder, Analytics, Replay, Shadow, Bounded Adaptive, Agent Policy. Do not promote a later stage until the earlier evidence gates pass.

System Interlink Verification

The green interlink seal is derived from live backend facts, not from a decorative animation. VERIFIED ACTIVE requires an API connection, fresh observation frames, a living target PID, Windows governor support, an armed governor, and a non-monitor-only applied QoS. OBSERVATION LINK means PulseFlow is integrated for measurement and recording but is not yet modulating a target process. Launch with Attach or Run to test causal smoothing against a baseline.
